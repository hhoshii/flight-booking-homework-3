# Бронирование авиабилетов — ДЗ №3

Реализованы поиск рейсов, создание и отмена бронирований с возвратом мест. Booking Service принимает REST-запросы и обращается к Flight Service по gRPC; у каждого сервиса своя PostgreSQL. Места резервируются и возвращаются в транзакциях, стоимость фиксируется при создании брони. Есть кеш Redis с TTL 5 минут и Sentinel, аутентификация межсервисных вызовов по API key, retry и Circuit Breaker. Запросы и переходы состояний пишутся в JSON-логи.

## Как запустить

Нужны Docker с Compose и make. Для демонстрации нужен Python 3. Все команды выполняются из корня проекта.

При первом запуске, если `.env` ещё нет:

```bash
cp .env.example .env
```

Затем:

```bash
docker compose up --build -d --wait
curl http://localhost:8080/health
```

Базы, миграции и демонстрационные рейсы создаются автоматически. Команда `curl` должна вернуть `{"status":"ok"}`. Значения в `.env.example` предназначены для локальной работы; свой `.env` в Git добавлять не нужно.

## Как пользоваться

API доступно на `http://localhost:8080`. Поиск рейсов — `GET /flights?origin=SVO&destination=LED&date=2026-12-01`, информация о рейсе — `GET /flights/{id}`. Параметр `date` можно опустить.

Для создания брони отправь `POST /bookings` с полями `user_id`, `flight_id`, `passenger_name`, `passenger_email` и `seat_count`. Созданная бронь получает статус `CONFIRMED`. Все цены передаются в копейках.

Получить бронь можно через `GET /bookings/{id}`, список броней пользователя — через `GET /bookings?user_id=...`. Для отмены есть `POST /bookings/{id}/cancel`: места возвращаются, статус меняется на `CANCELLED`.

Готовый пример «поиск → бронирование → отмена»:

```bash
make demo
```

Скрипт показывает команды `curl`, параметры и тела запросов, HTTP-статусы и JSON ответов. На свежей БД количество свободных мест меняется со 100 на 98 и обратно на 100. Отменённая бронь остаётся в БД.

Контракт Flight Service описан в [api/flight/v1/flight.proto](api/flight/v1/flight.proto). Go-код по нему генерируется при сборке. Ключ межсервисной аутентификации задаётся через `GRPC_API_KEY` в `.env`.

## Как проверить

После запуска системы выполни тесты:

```bash
docker compose --profile test run --rm test
```

Тесты запускаются в Docker с `-race`; Go отдельно устанавливать не нужно. Проверяются бронирование и отмена, транзакции, идемпотентность, кеш, аутентификация, retry и Circuit Breaker.

Проверка переключения Redis Sentinel:

```bash
python3 scripts/check_failover.py
```

Скрипт временно останавливает текущего мастера Redis, проверяет переключение на реплику и доступность API, затем запускает остановленный контейнер обратно.

С установленным Go можно выполнить `make test` для тестов и `go vet`, а также `make build` для сборки сервисов.

## Логи и остановка

```bash
docker compose logs -f booking-service flight-service
```

Ctrl+C завершает просмотр логов. Для остановки приложения с сохранением данных:

```bash
docker compose down
```
